- iOS `PurchaselyView.swift:170-203` : chemins `requestId`/`presentation` assignent `PurchaselyRN.purchaseResolve` **mort** (invocations supprimées par la réécriture v6) → `onPresentationClosed` ne fire jamais. Seul le chemin fresh `placementId` câble `.onDismissed`.
- iOS `PurchaselyViewManager.swift:13-14` : `purchaselyView`/`resolve` propriétés d'instance alors que Fabric + NativeModules peuvent créer 2 instances du manager (admis par le commentaire l.16-26) → forwarding de promise non fiable.
- Android `PurchaselyViewManager.kt:215` : `promiseView` global companion ; props placement/screen/requestId au niveau manager (partagées entre vues) → 2 vues embarquées se clobber.
- iOS `PurchaselyRN.m:1327` : chaque `preload()` ajoute à `presentationsLoaded` (legacy array) jamais nettoyé au dismiss (l.1411-1413 ne purge que `kPresentationsByRequest`) → rétention non bornée.
- JS `PLYPresentationView.tsx:59` : promise globale `NativeModules.PurchaselyView.onPresentationClosed()`, pas de routage par id.

Correction (aligner sur le mécanisme Flutter — lire `/Users/kevin/Purchasely/Flutter` `NativeView`/routing par requestId avant d'implémenter) :
1. Routage par identifiant : événement de dismiss émis par le natif avec `requestId` (préchargé) ou `viewId` généré côté composant (fresh path), payload = **PLYPresentationOutcome complet 5 champs** (identique full-screen).
2. iOS : câbler la détection de dismiss sur TOUS les chemins (préchargé compris — attacher le handler au moment du preload comme Flutter, routé par requestId) ; supprimer `purchaseResolve` (+ ses tests morts) ; purger `presentationsLoaded` au dismiss/réutilisation (ou remplacer par la map par requestId).
3. Android : supprimer `promiseView` global ; props stockées par vue (pas sur le manager) ; `outcomeHandler` émet l'événement routé ; éviction des maps `activePresentationRequests`/`activeLoadedPresentations` dans `onDropViewInstance` (hardening).
4. JS : `PLYPresentationView` s'abonne à l'événement filtré par son id ; `onPresentationClosed` reçoit `PLYPresentationOutcome` (remplace `PLYPresentationViewResult {result, plan}` — breaking vs rc, jamais GA, à documenter lot 3).
5. Tests : `PLYPresentationView.test.tsx` mis à jour (mount/unmount, routage par id, 2 vues simultanées, outcome complet) ; supprimer les asserts `purchaseResolve` de `PurchaselyRNTests.m`.
